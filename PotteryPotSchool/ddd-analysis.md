# DDD-анализ модуля критериального оценивания

## Предметная область

Система используется в учебном процессе. Преподаватель создаёт задания, студент сдаёт решения, преподаватель проверяет работы и выставляет оценки.

оценивание становится более детализированным: преподаватель заранее задаёт критерии оценивания, студент видит их до сдачи, при необходимости заполняет самооценку, а преподаватель проверяет работу по каждому критерию. Система автоматически рассчитывает итоговую оценку с учётом бонусов и штрафов.

## Основной бизнес-процесс

1. Преподаватель создаёт задание.
2. Преподаватель задаёт настройки оценивания.
3. Преподаватель добавляет критерии.
4. Студент открывает задание и видит критерии.
5. Студент сдаёт решение.
6. Если включена самооценка, студент заполняет её по критериям.
7. Преподаватель проверяет решение по критериям.
8. Система рассчитывает итоговую оценку.
9. Студент видит подробный результат проверки.

## Единый язык предметной области

Задание/Task - Учебная работа, которую должен выполнить студент.
Решение/Solution - Работа, которую студент или команда отправляет по заданию.
Критерий оценивания/Criterion - Правило, по которому преподаватель оценивает часть работы.
Тип критерия/CriterionType - Способ оценки критерия: баллы, да/нет или проценты.
Тип влияния/CriterionImpactType - Обычный или бонусный критерий.
Самооценка/SelfAssessment - Оценка студентом своей работы по тем же критериям.
Оценка преподавателя/TeacherAssessment - Оценка, которую преподаватель выставляет по критерию.
Оценка решения/SolutionGrade - Итог проверки решения с детализацией по критериям и штрафам.
Штраф за просрочку/LatePenalty - Штраф за сдачу после дедлайна.
Штраф за непоказ прогресса/ProgressPenalty - Штраф за указанное преподавателем количество непоказов.
Максимальная итоговая оценка/maxFinalScore - Максимум баллов за задание, не больше 100.

## Доменная модель

### Task

Задание определяет правила выполнения и проверки работы. В рамках новых требований задание содержит настройки критериального оценивания и список критериев.

Ответственность:
- хранить дедлайн
- хранить режим задания: индивидуальное или командное
- хранить настройки оценивания
- хранить критерии оценивания

### TaskGradingSettings

Настройки оценивания задания.

Поля:
- enabled
- maxFinalScore
- selfAssessmentRequired
- latePenaltyEnabled
- latePenaltyPerDay
- progressPenaltyEnabled
- progressPenaltyPerMiss

Ответственность:
- определять, включено ли оценивание по критериям
- определять, нужна ли самооценка
- определять, применяются ли штрафы
- задавать верхнюю границу итоговой оценки

### Criterion

Критерий оценивания, заданный преподавателем.

Поля:
- title
- description
- type
- maxScore
- impactType
- displayOrder

Ответственность:
- описывать, за что студент получает баллы
- определять способ расчёта баллов
- определять, является критерий обычным или бонусным

### Solution

Решение студента или команды.

Ответственность:
- хранить отправленную работу
- хранить статус решения
- хранить дату отправки
- хранить самооценку, если она требуется

### SelfAssessmentItem

Самооценка студента по конкретному критерию.

Ответственность:
- хранить значение самооценки
- хранить комментарий студента
- не влиять на итоговую оценку автоматически

### CriterionGradeItem

Оценка преподавателя по конкретному критерию.

Ответственность:
- хранить значение оценки
- хранить рассчитанные баллы
- хранить комментарий преподавателя

### SolutionGrade

Итоговая оценка решения.

Ответственность:
- хранить сумму обычных критериев
- хранить сумму бонусов
- хранить штрафы
- хранить итоговую оценку
- объяснять, как получился результат

## Бизнес-правила

### Правила задания

1. Если включено критериальное оценивание, у задания должны быть настройки оценивания.
2. maxFinalScore должен быть больше 0 и не больше 100.
3. Критерии создаются внутри задания, потому что студент должен видеть их до сдачи.
4. Критерий должен иметь тип: POINTS, YES_NO или PERCENT.
5. Критерий должен иметь тип влияния: REGULAR или BONUS.

### Правила самооценки

1. Если selfAssessmentRequired = true, студент обязан заполнить самооценку.
2. Самооценка заполняется по критериям задания.
3. Самооценка не влияет на итоговую оценку.
4. Преподаватель видит самооценку при проверке.

### Правила оценки преподавателя

1. Преподаватель выставляет оценку по каждому критерию.
2. Для POINTS указывается количество баллов от 0 до maxScore.
3. Для YES_NO значение true даёт maxScore, false даёт 0.
4. Для PERCENT баллы считаются по формуле: maxScore * percent / 100.
5. По каждому критерию преподаватель может оставить комментарий.

### Правила штрафов

1. Штраф за просрочку применяется только если latePenaltyEnabled = true.
2. Если работа сдана после дедлайна, количество дней просрочки умножается на latePenaltyPerDay.
3. Любая начавшаяся просрочка считается как полный день.
4. Штраф за непоказ прогресса применяется только если progressPenaltyEnabled = true.
5. Штраф за непоказ прогресса считается как progressMissesCount * progressPenaltyPerMiss.

### Правило итоговой оценки

Итоговая оценка считается по формуле:

finalScore = max(0, min(regularScore + bonusScore - latePenalty - progressPenalty, maxFinalScore))

Итоговая оценка:
- не может быть меньше 0
- не может быть больше maxFinalScore

## Границы ответственности

### Learning Content Context

Отвечает за учебный контент.

Сущности:
- Post
- Material
- Task
- Comment

Ответственность:
- создание постов
- публикация материалов
- создание заданий
- комментарии к постам

### Teamwork Context

Отвечает за командную работу.

Сущности:
- Team
- TeamRules
- TeamDistributionType

Ответственность:
- создание команд
- распределение студентов
- вступление и выход из команд
- командные решения

### Assessment Context

Отвечает за оценивание работ.

Сущности:
- TaskGradingSettings
- Criterion
- SelfAssessmentItem
- CriterionGradeItem
- SolutionGrade

Ответственность:
- настройка оценивания
- хранение критериев
- самооценка студента
- проверка преподавателем
- расчёт итоговой оценки
- применение штрафов

Новая функциональность была выделена в Assessment Context.
